# Flyway Migration Fix

## Issue
The `V2__seed_test_data.sql` migration was failing with:
```
ERROR: column "created_date_time" of relation "region" does not exist
```

## Root Cause
1. The SQL script was trying to insert into timestamp columns that are auto-generated by Hibernate
2. Column names may vary based on Hibernate naming strategy (`PhysicalNamingStrategyStandardImpl` preserves camelCase)
3. The migration was attempting to insert data before understanding the actual schema

## Solution
The migration file has been disabled by renaming it to `V2__seed_test_data.sql.disabled`.

**Use the Java TestDataSeeder component instead:**
- Set `app.seed.test-data=true` in `application-dev1.properties`
- The Java component handles entity relationships and column names correctly

## If Flyway History Needs Cleanup

If Flyway has already recorded a failed migration attempt, you may need to clean up the Flyway schema history:

```sql
-- Connect to your database and check Flyway history
SELECT * FROM flyway_schema_history WHERE script = 'V2__seed_test_data.sql';

-- If the migration is marked as failed, you can delete it:
DELETE FROM flyway_schema_history WHERE script = 'V2__seed_test_data.sql' AND success = false;
```

Or use Flyway's repair command:
```bash
mvn flyway:repair
```

## Alternative: Fix the SQL Migration

If you prefer SQL-based seeding, you would need to:
1. Check actual column names: `SELECT column_name FROM information_schema.columns WHERE table_name = 'region';`
2. Remove timestamp columns from INSERT statements (they're auto-generated)
3. Use correct column names based on your naming strategy

However, the Java TestDataSeeder is recommended as it's more maintainable and handles relationships better.
